# Как пользоваться DigUp MCP в Codex

DigUp MCP даёт Codex доступ к поиску по уже созданному локальному индексу DigUp. Вы описываете, что хотите найти,
а Codex вызывает поиск, получает подходящие фрагменты и использует их в ответе.

Сам DigUp устанавливается отдельно из [публичного проекта](https://github.com/ARahim3/DigUp): готовым выпуском,
пакетом или сборкой из исходников. MCP подключается к совместимой существующей установке и её индексу.
Приватный форк для этого не требуется. Для конкретного издания из App Store также нужны доступный поисковый
помощник и пути к индексу; такие пакеты отдельно не проверялись.

Руководство описывает MCP 0.1.1. Проверено 22 октября 2026 года: в текущем чате Codex работают проверка состояния,
смысловой поиск и получение фрагмента реальной заметки Obsidian.

## 1. Обычное использование

Пишите запрос прямо в чат Codex. Чтобы явно выбрать этот способ поиска, добавьте «через DigUp» или «через DigUp MCP».
Команды в терминале для повседневного поиска не нужны.

Например:

> Через DigUp найди мои материалы о суверенном искусственном интеллекте. Покажи пути к файлам и подходящие фрагменты.

После выдачи можно продолжить:

> Прочитай найденные фрагменты и кратко сопоставь основные идеи. Для каждого вывода укажи файл-источник.

Или уточнить:

> Получи более полный фрагмент из второго результата.

Открывать окно DigUp для поиска не требуется. MCP сам запускает установленный поисковый помощник. Docker для обычной
работы MCP на Mac не нужен; он использовался для проверки Linux.

## 2. Примеры запросов

| Задача | Что написать в Codex |
| --- | --- |
| Найти материал по смыслу | «Через DigUp найди, где у меня описаны способы хранения знаний и поиска по личным заметкам». |
| Найти известную заметку | «Через DigUp найди заметку “Технологическая позиция” и покажи подходящий фрагмент». |
| Выбрать результаты из Obsidian | «Через DigUp найди заметки о технологической позиции. Из результатов покажи файлы моего хранилища Obsidian». |
| Искать только PDF | «Через DigUp найди в PDF материалы о цифровых двойниках». |
| Искать исходный код | «Через DigUp найди в индексе кода реализацию повторного запроса после ошибки. Покажи файл и фрагмент». |
| Искать только по словам | «Через DigUp найди упоминания DIGUP_MODELS, используя только словесный поиск». |
| Проверить подключение | «Проверь состояние DigUp MCP и скажи, доступен ли индекс». |

Обычный поиск охватывает **весь основной индекс**. Исходный код ищется в отдельном индексе кода.

Отдельного параметра «папка» или «хранилище Obsidian» у текущего MCP нет. По просьбе «покажи только Obsidian» Codex
может выбрать подходящие пути из полученной выдачи. Это не гарантирует полный поиск исключительно по хранилищу:
сначала движок возвращает ограниченное число результатов из всего индекса. Если нужного результата нет, уточните
запрос или попросите увеличить выдачу, максимум до 50 результатов за один вызов.

## 3. Что происходит при поиске

1. Codex передаёт запрос движку DigUp через MCP.
2. DigUp ищет по словам и, по умолчанию, по смыслу в существующем индексе.
3. Codex получает пути, короткие выдержки и идентификаторы найденных фрагментов.
4. При необходимости Codex запрашивает текст подходящего фрагмента и отвечает с опорой на него.

Полученный фрагмент — текст из индекса, а не весь файл. Чтобы прочитать документ целиком, можно попросить:

> Открой исходную заметку по найденному пути и прочитай её целиком.

Чтение целого файла выполняется отдельными средствами Codex и зависит от доступных ему прав и формата файла.
Индексированный текст может отставать от последних изменений в исходнике.

Поисковый движок и индекс работают локально. Найденные выдержки и запрошенные фрагменты передаются в контекст чата
Codex для подготовки ответа.

## 4. Доступные инструменты

Названия и параметры нужны для точного запроса или диагностики; обычно Codex выбирает их сам.

| Инструмент | Назначение |
| --- | --- |
| `search` | Найти материалы в основном индексе или индексе кода. |
| `get_passage` | Получить индексированный текст фрагмента из результатов поиска. |
| `status` | Проверить подключение, состояние индекса и поисковой модели. |

Параметры `search`:

- `query` — поисковая фраза.
- `limit` — число результатов: от 1 до 50, по умолчанию 10.
- `code` — `true` для индекса кода; по умолчанию `false` для основного индекса.
- `kinds` — типы материалов: `doc`, `pdf`, `image`, `screenshot`, `audio`, `video`. Применяется к основному индексу.
- `meaning` — использовать смысловой поиск; по умолчанию `true`. Значение `false` выбирает словесный поиск.

Для `get_passage` Codex берёт `segment_id` из результата `search` и передаёт то же значение `code`.
Для изображений и некоторых медиа текстового фрагмента может не быть.

В **ответе** `search` поле `meaning: true` подтверждает, что смысловой поиск выполнился. Если модель недоступна,
MCP может вернуть словесные результаты с `meaning: false` и предупреждением. Это отличается от случая, когда вы
сами попросили искать только по словам.

## 5. Как новые файлы попадают в поиск

MCP использует готовый индекс и сам не запускает индексирование или скачивание модели. Новые и изменённые файлы
обрабатывает приложение DigUp либо CLI. Нужные папки должны быть выбраны для индексирования.

Для поиска по уже готовому индексу графическое приложение может быть закрыто. Чтобы индекс пополнялся автоматически
на Mac, оставляйте обычное приложение DigUp работающим в фоне.

Стандартная установка на Mac:

- приложение: `/Applications/DigUp.app`;
- установленный MCP: `~/.local/bin/digup-mcp`;
- общий индекс: `~/Library/Application Support/DigUp/index.noindex`;
- модель: `~/Library/Application Support/DigUp/Models`.

Если конкретный пакет DigUp хранит данные в другом месте, пути можно передать при подключении MCP через
`--binary`, `--index` и `--models`. Параметры описаны в [README](../README.md#configure-digup-paths).

На Linux тот же MCP обращается к установленному Linux CLI и локальному индексу этой машины. По умолчанию данные
находятся в `~/.local/share/digup` либо в `$XDG_DATA_HOME/digup`, если задан `XDG_DATA_HOME`.
Подключение MCP на Mac само по себе не даёт доступ к индексу VPS.

## 6. Если что-то не работает

**Codex не видит DigUp.** Попросите: «Проверь, доступен ли в этом чате инструмент DigUp MCP».
Если инструментов нет, откройте настройки приложения → MCP servers, проверьте, что сервер `digup` включён,
и перезапустите его через Restart. Затем начните новый чат. Порядок управления подключениями описан
в [официальной документации OpenAI](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Дополнительная проверка из терминала:

```sh
codex mcp get digup
```

Это проверяет регистрацию сервера; фактическую работу поиска подтверждает вызов `search` из чата.
Установка и подключение на другой машине описаны в [README](../README.md#install).

**Запрос не находит известный файл.** Уточните название или характерные слова и попросите показать пути результатов.
Проверьте, что папка выбрана в DigUp и файл уже обработан. Пустая выдача не доказывает отсутствие файла на диске.

**В статусе `vectors: 0` или `encoder: stopped`.** Во время простоя поисковая модель и векторы могут быть выгружены
из памяти. Само по себе это не означает потерю индекса. Проверьте обычным поисковым запросом; первый запрос после
простоя может занять больше времени.

**В выдаче есть предупреждение о словесном поиске.** Попросите Codex сообщить причину из предупреждения и проверить
доступность модели. Такие результаты нельзя представлять как успешно выполненный смысловой поиск.
